# Mastering Input Management: Variable File Patterns

The `.tfvars` file is the primary tool for providing environment-specific data to a single Terraform configuration. While Terraform automatically loads files named `terraform.tfvars`, a professional DevOps engineer uses explicit variable file patterns to manage the complexity of Development, Staging, and Production environments. This chapter explores the technical patterns for organizing, naming, and injecting variable files into the Terraform lifecycle.

## 1. The Variable Loading Hierarchy

Understanding the order of precedence is critical when using multiple variable files. Terraform resolves variables in the following order (last one wins):

1. **Environment Variables:** `TF_VAR_variable_name`.
2. **`terraform.tfvars`**: Automatically loaded.
3. **`terraform.tfvars.json`**: Automatically loaded.
4. **`*.auto.tfvars`**: All files with this suffix are loaded in alphabetical order.
5. **`-var-file` Flags:** Variables passed explicitly at the CLI.
6. **`-var` Flags:** Individual variables passed at the CLI.

By using the `-var-file` flag, you explicitly override any default values or auto-loaded files, providing a high-confidence environment context.

## 2. The Multi-Environment Pattern

This is the most common pattern for projects managed with Terraform workspaces or a single root module.

### 2.1 Directory Structure
```text
infrastructure/
├── main.tf
├── variables.tf
└── vars/
    ├── dev.tfvars
    ├── staging.tfvars
    └── prod.tfvars
```

### 2.2 Execution Logic
You map your command-line execution to the specific environment file:
```bash
terraform workspace select prod
terraform plan -var-file="vars/prod.tfvars"
```
This pattern ensures that you aren't manually typing 50 variables at the command line every time you deploy.

## 3. Global vs. Regional Patterns

In global deployments, you often have variables that are constant across all regions (e.g., `project_owner`) and variables that change per region (e.g., `ami_id`).

**The Multiple Flag Pattern:**
```bash
terraform plan \
  -var-file="vars/global.tfvars" \
  -var-file="vars/us-east-1.tfvars"
```
Terraform merges these files. If a variable exists in both, the last one specified (`us-east-1.tfvars`) takes precedence.

## 4. The JSON Variable Pattern

Terraform also supports JSON-formatted variable files (`.json.tfvars`).

**Use Case: Integration with external systems.**
If your "Staging" environment parameters are generated by an external CMDB or a custom Python script, have that script output a JSON file.
```json
{
  "instance_type": "t3.medium",
  "disk_size": 100,
  "enable_monitoring": true
}
```
Terraform parses this natively, allowing for seamless integration between your IaC and other automated platform tools.

## 5. Security and .gitignore Best Practices

Variable files often contain the exact IP addresses, account IDs, and architecture details of your infrastructure.

- **Non-Sensitive Data:** `dev.tfvars` can be committed to Git to serve as "documentation-as-code."
- **Sensitive Data:** Never commit files containing passwords, API keys, or database credentials.
- **The `.gitignore` Rule:** Always add `*.secret.tfvars` and `secrets.tfvars` to your `.gitignore`. Use a secrets manager (AWS Secrets Manager, Vault) to inject those values at runtime instead of relying on local files.

## 6. Using `*.auto.tfvars` for Defaults

If you have sub-modules or complex local development needs, you can use `.auto.tfvars` to provide "Sticky" defaults that don't need a command-line flag. This is useful for:
- Developer-specific overrides (e.g., `personal.auto.tfvars`).
- Shared module defaults that differ from the core repository defaults.

## 7. Validating Your Variable Files

Since variable files are just key-value pairs, they aren't checked for types until the `plan` phase begins.

- **Consistency Check:** Ensure that every key specified in your `.tfvars` file is also defined in your `variables.tf`. If you provide a variable in the file that isn't declared in code, Terraform will return an error.
- **Automation Tip:** Use `tflint` to scan your `.tfvars` files against your schema to catch errors before reaching the cloud.

## 8. Summary

Variable files are the bridge between your generic infrastructure code and your specific environment reality. By adopting a structured `-var-file` pattern, utilizing JSON for automation, and strictly separating sensitive metadata from configuration, you create a deployment process that is both flexible and secure. Mastering the loading precedence and organization of these files is essential for scaling Terraform across complex, multi-region architectures and collaborative DevOps teams.
